# ADR-001: Кімнати та контроль їх зайнятості

- Статус: `Proposed`
- Дата створення: 2026-07-20
- Власник рішення: Product owner + tech lead
- Цільова дата рішення: 2026-07-22
- Залежні етапи: 1, 2, 4, 6

## Контекст

Специфікація описує одну клініку без філій, але картки запису й пацієнта показують поле «кабінет». Вона прямо забороняє перетин записів одного спеціаліста, проте не визначає, чи одна кімната може одночасно обслуговувати різних спеціалістів. Прототип використовує значення на кшталт «Кабінет 1».

## Запропоноване рішення

- Організація має одну локацію без сутності `Branch`.
- `Room` є окремим довідником цієї локації; підтримуються кілька активних кімнат.
- Новий appointment повинен мати активну `room_id`; для імпортованої історії дозволений лише snapshot назви без активного FK.
- Перетини незавершених appointment блокуються незалежно за `specialist_id` і за `room_id` на DB-рівні.
- Лише статус `canceled` звільняє часовий слот; `completed` і `no_show` зберігають історичну зайнятість.
- Деактивація кімнати забороняє нові записи, але не змінює історію.
- Початковий seed створює `Кабінет 1`; адміністратор може керувати кімнатами без створення філій.

## Наслідки

- Availability API приймає або повертає кімнату та перевіряє два незалежні конфлікти.
- `Appointment` має FK на `Room` і snapshot назви кімнати.
- Потрібен другий PostgreSQL exclusion constraint для `room_id`/`time_range`.
- Паралельні записи різних спеціалістів допустимі лише в різних кімнатах.
- UI повинен окремо пояснювати конфлікт спеціаліста та конфлікт кімнати.

## Відхилені альтернативи

- Текстова мітка без constraint: не захищає від подвійного використання фізичного ресурсу.
- Одна жорстко задана кімната без довідника: суперечить наявному UI й ускладнює безпечне розширення.
- Філії/локації: прямо поза межами MVP.

## Критерії перевірки

- Два concurrent POST для тієї самої кімнати й часу: рівно один успішний.
- Два спеціалісти в різних кімнатах у той самий час: обидва записи успішні.
- Скасований запис звільняє кімнату; завершений і `no_show` — ні.
