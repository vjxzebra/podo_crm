# ADR-002: Єдиний графік кабінету

- Статус: `Accepted`
- Дата створення: 2026-07-20
- Дата погодження: 2026-07-20
- Власник рішення: Product owner
- Цільова дата рішення: 2026-07-22
- Залежні етапи: 2, 4, 6

## Контекст

Специфікація вимагає робочий/вихідний стан, початок, завершення та кілька перерв для кожного дня тижня. Вона прямо виключає індивідуальні графіки спеціалістів, свята, відпустки, винятки, horizon booking, налаштування часового поясу й кроку календаря. Водночас прототип демонструє різні години працівників.

## Рішення

- У MVP існує один повторюваний тижневий графік клініки.
- `ClinicWorkday` і `ClinicBreak` не мають FK на спеціаліста.
- Availability є перетином графіка клініки з відсутністю конфліктів спеціаліста та кімнати.
- Усі серверні timestamps зберігаються в UTC; бізнес-час MVP фіксований як `Europe/Kyiv` і не редагується в UI.
- Індивідуальні графіки, відпустки, свята та разові винятки не моделюються.
- Відмінні години працівників у прототипі вважаються демонстраційною невідповідністю, а не вимогою.

## Наслідки

- Налаштування робочого часу має одну тижневу форму для всього кабінету.
- Неможливо позначити окремого спеціаліста недоступним інакше, ніж наявним appointment; це свідоме обмеження MVP.
- Перерви повинні бути всередині робочого дня, не перетинатися й мати `end > start`.
- Task packets не повинні додавати specialist schedule fields або UI без нового ADR.

## Відхилені альтернативи

- Графік на кожного спеціаліста: додає scope, який специфікація прямо виключає.
- Повний календар винятків: потребує окремих правил пріоритету й не входить до MVP.

## Критерії перевірки

- Запис поза робочим днем або під час перерви відхиляється.
- Одна зміна графіка впливає на availability усіх спеціалістів.
- API та production UI не містять specialist schedule, holiday або vacation contracts.
